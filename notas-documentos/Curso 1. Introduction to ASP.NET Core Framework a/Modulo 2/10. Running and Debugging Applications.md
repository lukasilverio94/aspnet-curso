### Runtime Execution Errors

Runtime errors occur during request processing and often manifest as HTTP 500 responses. Null reference exceptions suggest missing data validation or improper null handling. Database connection failures indicate infrastructure problems or incorrect connection configuration. Routing errors result in HTTP 404 responses when the framework cannot match requests to controller actions.

### Performance-Related Issues

Performance problems often appear as slow response times rather than explicit errors. Database queries without proper indexing cause delays that compound under load. Memory leaks gradually degrade performance until the application becomes unresponsive. Inefficient LINQ queries or excessive API calls create bottlenecks that affect user experience.

## Environment Variables and Application Behavior

Environment variables help configure behavior without changing code—but they can also introduce hard-to-trace bugs.

### Configuration Precedence and Debugging

ASP.NET Core loads configuration from multiple sources with a defined precedence order.

Configuration sources override in this order:

1. appsettings.json  
    
2. Environment-specific JSON file  
    
3. Environment variables  
    
4. Command-line arguments
    

Understanding this hierarchy helps you identify why your application might behave differently in various environments. A setting that works locally might be overridden by an environment variable in production, causing unexpected behavior that's difficult to trace without systematic investigation.

### Common Environment-Related Issues

Incorrectly set environment variables cause some of the most frustrating debugging scenarios. An application accidentally running in Development mode in production exposes sensitive error information. Database connection strings pointing to the wrong environments cause data-related issues. Missing environment variables for API keys or external service configurations result in runtime failures that may not be immediately obvious.
