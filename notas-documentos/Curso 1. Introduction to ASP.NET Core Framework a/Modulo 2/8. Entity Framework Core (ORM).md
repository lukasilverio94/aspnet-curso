## Introduction

Building APIs that lose all data on restart isn't just frustrating—it’s impractical in real applications. Professional developers need robust data persistence solutions that can handle complex business requirements while maintaining high performance.

In this reading, you’ll explore how Entity Framework Core (EF Core) pairs with minimal APIs to deliver enterprise‑grade data persistence, relational modeling, and concurrency support. You'll learn the fundamental concepts that transform your lightweight API from a prototype into a production-ready application that can persist data, model complex relationships, and handle concurrent users efficiently.

## Understanding Entity Framework Core

Entity Framework Core is Microsoft's modern object-relational mapping (ORM) framework that bridges the gap between your C# objects and database tables. Instead of writing raw SQL queries and manually managing database connections, EF Core allows you to work with your data using familiar C# classes and LINQ queries.

Think of EF Core as a translator between your C# domain model and your database tables. When you create a Task object in your code, EF Core knows how to store it as a row in a database table. When you query for tasks, EF Core translates your LINQ expressions into optimized SQL queries and converts the results back into C# objects.

This abstraction provides several critical benefits for API development. First, it dramatically reduces the amount of code you need to write and maintain. Instead of crafting SQL statements for every operation, you can focus on your business logic while EF Core handles the data access complexity. Second, it provides a layer of protection against SQL injection attacks and other security vulnerabilities. Third, it makes your code more maintainable by keeping your data access logic organized and testable.

### The DbContext: Your Data Gateway

At the heart of Entity Framework Core lies the DbContext class, which serves as your primary interface for database operations. The DbContext acts as a combination of the Unit of Work and Repository patterns, managing database connections, tracking changes to your entities, and coordinating the persistence of data.

Each DbSet<T> represents a table, and T is the type that defines the shape of each row. When you create a custom DbContext class for your application, you define DbSet properties that represent the tables in your database. Each DbSet<T> property gives you access to a collection of entities in a table. The DbContext tracks all changes you make to these entities and can persist them to the database when you call SaveChanges() or SaveChangesAsync().

The DbContext also manages the database connection lifecycle automatically. You don't need to be concerned about opening and closing connections, managing connection pooling, or dealing with connection timeouts. EF Core handles these infrastructure concerns, allowing you to focus on your application's business logic.

## Code First Development Approach

Entity Framework Core embraces a "Code First" development methodology, where you define your data model using C# classes and let EF Core generate the corresponding database schema. This approach offers significant advantages for modern development workflows, particularly when building APIs.

With Code First, your entity classes serve as the single source of truth for your data model. These are simple C# classes, often called POCOs (Plain Old CLR Objects), that represent the business entities in your domain. For example, a Task entity might include properties for Id, Title, Description, IsCompleted, and DueDate.

EF Core uses these entity classes to understand the structure of your database and can automatically create tables, columns, relationships, and constraints based on your class definitions. This automation extends beyond initial database creation—EF Core can also generate and apply database migrations when you modify your entity classes, keeping your database schema in sync with your code changes.

The Code First approach promotes better software engineering practices by keeping your data model close to your business logic. When you need to add a new property to an entity, you simply add it to your C# class and generate a migration. This process is easier to maintain than writing manual SQL scripts across environments.

## Dependency Injection Integration

Modern minimal APIs rely heavily on dependency injection to manage object lifecycles and promote testable, maintainable code. Entity Framework Core integrates seamlessly with .NET's built-in dependency injection container, making it easy to use your DbContext throughout your application.

When you register your DbContext with the dependency injection container, you specify how EF Core should create and manage DbContext instances. Typically, you register your DbContext as a scoped service so each request gets a unique instance.

This integration provides several benefits for API development. First, it ensures that your DbContext instances are properly managed and disposed of, preventing memory leaks and connection exhaustion. Second, it makes your endpoint handlers easily testable by allowing you to inject mock or in-memory database contexts. Third, it promotes loose coupling between your API endpoints and your data access logic.

In your minimal API endpoints, you can request a DbContext instance simply by adding it as a parameter to your endpoint handler. The dependency injection system automatically provides a properly configured DbContext instance, and you can immediately start using it to query or modify data.

## CRUD Operations with Entity Framework Core

Creating, reading, updating, and deleting data (CRUD operations) form the foundation of most API functionality. Entity Framework Core provides intuitive, strongly-typed methods for performing these operations while handling the underlying SQL generation and execution.

### Creating Data

Adding new data to your database involves creating new entity instances and adding them to the appropriate DbSet. When you call context.Tasks.Add(newTask), EF Core begins tracking the entity as a new object that should be inserted into the database. The actual database insertion happens when you call SaveChangesAsync(), which generates and executes the appropriate INSERT statement.

EF Core automates many data creation steps. For entities with auto-generated primary keys, EF Core ensures that the generated key values are populated back into your entity objects after the save operation completes. It also manages foreign key relationships, ensuring that related entities are saved in the correct order to satisfy database constraints.

### Reading Data

Querying data with Entity Framework Core leverages LINQ (Language Integrated Query), allowing you to write database queries using familiar C# syntax. When you write expressions like context.Tasks.Where(t => t.IsCompleted == false), EF Core translates these into optimized SQL queries and executes them against your database.

EF Core offers async query methods for common use cases:

- ToListAsync() for multiple records
    
- FirstOrDefaultAsync() when zero or one is expected
    
- SingleOrDefaultAsync() when exactly one is required
    

### Updating Data

Updating existing data typically involves retrieving an entity, modifying its properties, and saving the changes. EF Core tracks changes and only generates UPDATE SQL for modified property values.

For scenarios where you need to update multiple records or perform bulk operations, EF Core provides additional approaches such as executing raw SQL commands or using bulk update extensions. However, for most API scenarios, the standard approach of retrieving, modifying, and saving individual entities provides the best balance of simplicity and performance.

In some cases, especially when working with disconnected entities, you might set the entity’s state explicitly using context.Entry(entity).State = EntityState.Modified.

### Deleting Data

Removing data from your database can be accomplished by retrieving the entity and calling the Remove() method on the appropriate DbSet. EF Core handles the generation of DELETE statements and manages any cascade delete operations based on your configured relationships.

For better performance in scenarios where you only need to delete by primary key, EF Core allows you to create a temporary entity with just the key property set and remove it without first querying the database. This approach minimizes database round-trips while still providing the safety and consistency benefits of using the ORM.

## Asynchronous Programming Patterns

Modern web APIs must handle numerous concurrent requests efficiently, and blocking database operations can severely impact application performance. Entity Framework Core embraces asynchronous programming throughout its API surface, providing async versions of all major operations.

Using async methods like FindAsync(), ToListAsync(), SaveChangesAsync(), and FirstOrDefaultAsync() allows your API endpoints to remain responsive while database operations are in progress. Instead of blocking a thread while waiting for database results, these methods free up the thread to handle other requests, strikingly improving your application's scalability.

Using synchronous methods in a high-concurrency web server can lead to thread starvation and degraded performance.

The async/await pattern lets you write asynchronous code that's readable and maintainable. Use methods like FindAsync() or SaveChangesAsync() to keep your API responsive under load. In your minimal API endpoints, you simply mark your handler methods as async and use the await keyword when calling EF Core methods. The .NET runtime handles the complexity of managing the asynchronous operations and ensuring that your code resumes execution on an appropriate thread when the database operation completes.

This asynchronous approach becomes particularly important when your API needs to handle high traffic loads or when database operations involve complex queries that may take longer to execute. By embracing async patterns from the beginning, you build APIs that can scale effectively as your user base grows.
