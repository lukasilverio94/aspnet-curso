
# Introduction 

Dependency Injection (DI) is a core design pattern in ASP.NET Core, enabling applications to achieve greater modularity, flexibility, and ease of maintenance. By allowing dependencies to be injected externally, DI minimizes direct dependencies between classes and external services, fostering a more adaptable and resilient codebase. This reading reviews the role of DI in building well-structured, performant applications and explores how DI supports testing through unit tests with mock services.

## Key Concepts of Dependency Injection

- Dependencies and services: A dependency is any external service or object a class relies on to function. In ASP.NET Core, DI manages these dependencies by supplying required services to classes from an external source, which promotes flexibility in code structure and enables smooth integration of various services.
    
- Tight vs. loose coupling: In tightly coupled systems, components are interdependent, making code more challenging to maintain. DI promotes loose coupling by injecting dependencies from external sources. This design pattern reduces the risk of system-wide changes due to updates in a single component and improves overall flexibility.
    

### Benefits of Using Dependency Injection

- Improved flexibility: DI allows developers to swap out implementations easily, such as changing authentication methods, without modifying the core code.
    
- Enhanced performance: DI efficiently manages service instances, optimizing performance by creating new instances as needed or reusing them where possible, which is critical in handling high request volumes.
    
- Simplified maintenance: With DI, updates to services impact only the areas where they’re explicitly injected, enabling seamless upgrades and minimizing potential errors from code changes.
    

## Dependency Injection in Unit Testing

- Mocking with DI: DI enables mock services in testing, where developers simulate external dependencies to isolate and validate individual components. Mocking ensures tests are focused and reliable, free from the complexities of actual service integrations.
    
- Testing process with DI:
    
    - Set up the environment: Configure the component to use mock services.
        
    - Define mock behavior: Use a mocking framework to emulate the expected behavior of dependencies.
        
    - Run and validate: Execute the test, confirming the component's behavior under predefined conditions.
        
    - Use a test runner: Execute the unit test to check component responses, ensuring isolated, accurate results.
        

# Conclusion 

Dependency Injection in ASP.NET Core is essential for developing flexible, maintainable, high-performance applications. DI facilitates loose coupling and modularity, allowing applications to adapt to new requirements seamlessly. Additionally, DI supports robust testing practices through mock services, making it easier to build reliable, testable code that can evolve efficiently as application needs change.

Veja os passos, começando no 1, criando uma CustomIService e um Service, aí vamos injetar e criar alguns middlewares para logar esse Service

```cs
var builder = WebApplication.CreateBuilder(args);

// 2. Register this new custom Service
// Podemos substituir qualquer MyService por algum outro Service que implementa a interface IMyService.
// Sendo mto mais fácil de manter - Singleton cria apenas 1 instância do objeto, 
// não importa quantas vezes é chamado
builder.Services.AddSingleton<IMyService, MyService>();

var app = builder.Build();

// middleware to use in other contexts
app.Use(async(context, next) =>
    {
    var myService = context.RequestServices.GetRequiredService<IMyService>();
    myService.LogCreation("First Middleware");
    await next.Invoke(); 
});

app.Use(async(context, next) =>
    {
    var myService = context.RequestServices.GetRequiredService<IMyService>();
    myService.LogCreation("Second Middleware");
    await next.Invoke(); 
});

// 3. Inject on the Route the new Service
app.MapGet("/", (IMyService myService) =>
{
    myService.LogCreation("Root");
    return Results.Ok("Check the console for service creation logs");
});

app.Run();


// 1. Creating a custom Interface / Service
public interface IMyService
{
    void LogCreation(string message);
}

public class MyService: IMyService
{
    private readonly int _serviceId;
    public MyService()
    {
        _serviceId = new Random().Next(100000, 999999);
    }

    public void LogCreation(string message)
    {
        Console.WriteLine($"{message} - Service ID: {_serviceId}");
    }
}
```
