Creating Well-Structured Entity Models in Entity Framework Core

Introduction

Creating well-structured entity models in Entity Framework Core is like building the foundation of a house—get it right from the start and everything else becomes easier. This tutorial demonstrates how to create entity classes, configure relationships, and implement validation that creates a solid foundation for your data layer.

Core Concept: This demonstration builds a complete e-commerce domain model with entities for Customer, Order, Product, and Category, showcasing both simple and complex relationship configurations using data annotations and Fluent API.

Learning Objectives

  • Create entity classes with proper naming conventions
  • Apply data annotations for validation and configuration
  • Configure one-to-many relationships
  • Implement many-to-many relationships
  • Use Fluent API for advanced relationship configuration
  • Configure cascade delete behavior
  • Test entity models with migrations and sample data

Creating the Customer Entity

The Customer entity serves as the foundation of our e-commerce model, demonstrating basic entity structure, data annotations, and navigation properties.

Customer.cs

using System.ComponentModel.DataAnnotations;

namespace YourNamespace.Models
{
    public class Customer
    {
        public int Id { get; set; }

        [Required(ErrorMessage = "First name is required")]
        [MaxLength(50)]
        public string FirstName { get; set; } = string.Empty;

        [Required(ErrorMessage = "Last name is required")]
        [MaxLength(50)]
        public string LastName { get; set; } = string.Empty;

        [Required(ErrorMessage = "Email is required")]
        [EmailAddress(ErrorMessage = "Invalid email address")]
        [MaxLength(100)]
        public string Email { get; set; } = string.Empty;

        [MaxLength(15)]
        public string? Phone { get; set; }

        // Navigation property - one-to-many relationship
        public ICollection<Order> Orders { get; set; } = new List<Order>();
    }
}

Data Annotations Explained

[Required]
Ensures that fields cannot be null. Provides a custom error message when validation fails
[MaxLength]
Sets database column length limits, preventing data truncation and ensuring consistent storage requirements
[EmailAddress]
Provides format validation to ensure the value is a valid email address
Navigation Property (Orders)
Establishes a one-to-many relationship, allowing access to all orders for a customer through the object model. Initialized to an empty list to avoid null reference issues

Creating the Order Entity

The Order entity demonstrates foreign key configuration and relationships back to the Customer entity.

Order.cs

using System.ComponentModel.DataAnnotations;
using System.ComponentModel.DataAnnotations.Schema;

namespace YourNamespace.Models
{
    public class Order
    {
        public int Id { get; set; }

        [Required]
        public DateTime OrderDate { get; set; }

        [Column(TypeName = "decimal(18,2)")]
        public decimal TotalAmount { get; set; }

        [MaxLength(20)]
        public string Status { get; set; } = "Pending";

        // Foreign key
        public int CustomerId { get; set; }

        // Navigation property - many-to-one relationship
        public Customer Customer { get; set; } = null!;

        // Navigation property - one-to-many relationship
        public ICollection<OrderItem> OrderItems { get; set; } = new List<OrderItem>();
    }
}

Key Components

Scalar Properties
Properties like Id, OrderDate, TotalAmount, and Status store actual data values
CustomerId (Foreign Key)
Serves as the foreign key property that references the related Customer entity
Customer (Navigation Property)
Provides object-oriented access to the related Customer entity
[Column] Attribute
Specifies exact decimal precision for monetary values (18 digits total, 2 decimal places), ensuring accurate financial calculations
Design Pattern: The Order entity includes both the foreign key property (CustomerId) and the navigation property (Customer), following Entity Framework Core best practices for explicit relationship configuration.

Creating the Product Entity

The Product entity demonstrates how one entity can participate in multiple relationships—with both Categories (many-to-many) and OrderItems (one-to-many).

Product.cs

using System.ComponentModel.DataAnnotations;
using System.ComponentModel.DataAnnotations.Schema;

namespace YourNamespace.Models
{
    public class Product
    {
        public int Id { get; set; }

        [Required(ErrorMessage = "Product name is required")]
        [MaxLength(100)]
        public string Name { get; set; } = string.Empty;

        [MaxLength(500)]
        public string? Description { get; set; }

        [Column(TypeName = "decimal(18,2)")]
        public decimal Price { get; set; }

        public int StockQuantity { get; set; }

        // Navigation properties
        // Many-to-many relationship with Category
        public ICollection<Category> Categories { get; set; } = new List<Category>();

        // One-to-many relationship with OrderItem
        public ICollection<OrderItem> OrderItems { get; set; } = new List<OrderItem>();
    }
}

Multiple Relationship Participation

The Product entity showcases Entity Framework Core's ability to handle multiple relationships simultaneously:

  • Categories: Many-to-many relationship allowing products to belong to multiple categories
  • OrderItems: One-to-many relationship tracking which orders include this product

Creating the Category Entity

The Category entity completes the many-to-many relationship with Product, establishing the relationship from both directions.

Category.cs

using System.ComponentModel.DataAnnotations;

namespace YourNamespace.Models
{
    public class Category
    {
        public int Id { get; set; }

        [Required(ErrorMessage = "Category name is required")]
        [MaxLength(50)]
        public string Name { get; set; } = string.Empty;

        [MaxLength(200)]
        public string? Description { get; set; }

        // Navigation property - many-to-many relationship
        public ICollection<Product> Products { get; set; } = new List<Product>();
    }
}
Many-to-Many Relationships: The Category entity mirrors the Product entity's navigation property. When both entities include collection navigation properties pointing to each other, Entity Framework Core recognizes this as a many-to-many relationship and automatically creates a join table.

Creating the OrderItem Entity (Linking Entity)

OrderItem serves as a linking entity that contains both foreign keys and additional properties specific to the relationship between Order and Product.

OrderItem.cs

using System.ComponentModel.DataAnnotations;
using System.ComponentModel.DataAnnotations.Schema;

namespace YourNamespace.Models
{
    public class OrderItem
    {
        public int Id { get; set; }

        [Required]
        public int Quantity { get; set; }

        [Column(TypeName = "decimal(18,2)")]
        public decimal UnitPrice { get; set; }

        // Foreign keys
        public int OrderId { get; set; }
        public int ProductId { get; set; }

        // Navigation properties
        public Order Order { get; set; } = null!;
        public Product Product { get; set; } = null!;
    }
}

Linking Entity Characteristics

  • Dual Foreign Keys: Contains OrderId and ProductId to reference both related entities
  • Relationship-Specific Data: Includes Quantity and UnitPrice properties that are specific to this particular order-product combination
  • Dual Navigation Properties: Provides object-oriented access to both the Order and Product entities
When to Use Linking Entities: Use explicit linking entities (like OrderItem) instead of automatic join tables when you need to store additional data about the relationship itself. Automatic join tables only store the foreign keys, while linking entities can include extra properties like Quantity and UnitPrice.

Configuring Relationships with Fluent API

While data annotations provide basic configuration, Fluent API offers more control and keeps configuration logic centralized in the DbContext class.

ApplicationDbContext.cs

using Microsoft.EntityFrameworkCore;
using YourNamespace.Models;

namespace YourNamespace.Data
{
    public class ApplicationDbContext : DbContext
    {
        public ApplicationDbContext(DbContextOptions<ApplicationDbContext> options)
            : base(options)
        {
        }

        public DbSet<Customer> Customers { get; set; }
        public DbSet<Order> Orders { get; set; }
        public DbSet<Product> Products { get; set; }
        public DbSet<Category> Categories { get; set; }
        public DbSet<OrderItem> OrderItems { get; set; }

        protected override void OnModelCreating(ModelBuilder modelBuilder)
        {
            base.OnModelCreating(modelBuilder);

            // Configure Customer-Order relationship (one-to-many)
            modelBuilder.Entity<Order>()
                .HasOne(o => o.Customer)
                .WithMany(c => c.Orders)
                .HasForeignKey(o => o.CustomerId)
                .OnDelete(DeleteBehavior.Restrict);

            // Configure Product-Category relationship (many-to-many)
            modelBuilder.Entity<Product>()
                .HasMany(p => p.Categories)
                .WithMany(c => c.Products);

            // Configure Order-OrderItem relationship (one-to-many)
            modelBuilder.Entity<OrderItem>()
                .HasOne(oi => oi.Order)
                .WithMany(o => o.OrderItems)
                .HasForeignKey(oi => oi.OrderId)
                .OnDelete(DeleteBehavior.Cascade);

            // Configure Product-OrderItem relationship (one-to-many)
            modelBuilder.Entity<OrderItem>()
                .HasOne(oi => oi.Product)
                .WithMany(p => p.OrderItems)
                .HasForeignKey(oi => oi.ProductId)
                .OnDelete(DeleteBehavior.Restrict);
        }
    }
}

Fluent API Configuration Breakdown

Customer-Order Relationship

modelBuilder.Entity<Order>()
    .HasOne(o => o.Customer)           // Each order has one customer
    .WithMany(c => c.Orders)            // Each customer has many orders
    .HasForeignKey(o => o.CustomerId)   // Foreign key specification
    .OnDelete(DeleteBehavior.Restrict); // Prevent cascade delete

This configuration explicitly defines the one-to-many relationship between Customer and Order. The OnDelete(DeleteBehavior.Restrict) prevents customers from being deleted if they have orders.

Product-Category Relationship

modelBuilder.Entity<Product>()
    .HasMany(p => p.Categories)    // Each product has many categories
    .WithMany(c => c.Products);     // Each category has many products

This simple configuration establishes the many-to-many relationship. Entity Framework Core 5.0 and later automatically creates the necessary join table for this relationship.

Order-OrderItem Relationship with Cascade Delete

modelBuilder.Entity<OrderItem>()
    .HasOne(oi => oi.Order)
    .WithMany(o => o.OrderItems)
    .HasForeignKey(oi => oi.OrderId)
    .OnDelete(DeleteBehavior.Cascade);  // Cascade delete enabled

The OnDelete(DeleteBehavior.Cascade) ensures that when an order is deleted, all related order items are automatically removed, preventing orphaned records in the database.

Fluent API Advantages: Fluent API provides more configuration options than data annotations, keeps configuration centralized, and allows configuration of features that don't have data annotation equivalents (like cascade delete behavior).

Understanding Delete Behaviors

DeleteBehavior.Cascade
When a parent entity is deleted, all related child entities are automatically deleted. Used for OrderItem to ensure no orphaned items remain when an order is deleted
DeleteBehavior.Restrict
Prevents deletion of a parent entity if related child entities exist. Used for Customer-Order relationship to prevent accidental loss of order history
DeleteBehavior.SetNull
Sets foreign key properties to null when the parent entity is deleted. Only works with nullable foreign keys
DeleteBehavior.NoAction
No automatic action is taken. The database handles the constraint, which may result in an error if related entities exist
Best Practice: Choose cascade delete carefully based on business requirements. Use Cascade for true dependent entities (like OrderItems that have no meaning without their Order), and use Restrict for entities that should be preserved independently (like Customers who have order history).

Testing Model Configuration with Migrations

Creating a migration validates your entity model configuration and shows how Entity Framework Core interprets your design.

Create Initial Migration

dotnet ef migrations add InitialCreate
Important: The migration name "InitialCreate" is case-sensitive.

The generated migration file appears in the Migrations folder and reveals how Entity Framework Core interpreted your model configuration, including:

  • Table structures with all columns and data types
  • Primary key definitions
  • Foreign key relationships and constraints
  • Indexes for performance optimization
  • Delete behavior configurations

Review Generated Migration

The migration file shows the CreateTable operations for each entity, including:

  • Column definitions matching your property types and annotations
  • Foreign key constraints with proper cascade/restrict behavior
  • Join tables for many-to-many relationships (ProductCategory)
  • Index creation for foreign keys to improve query performance

Testing Models with Sample Data

Creating a data seeder verifies that navigation properties and relationships work correctly in practice.

DataSeeder.cs

using YourNamespace.Data;
using YourNamespace.Models;

namespace YourNamespace.Data
{
    public class DataSeeder
    {
        public static void SeedData(ApplicationDbContext context)
        {
            // Clear existing data
            context.Database.EnsureCreated();

            if (context.Customers.Any())
            {
                return; // Database already seeded
            }

            // Create customers
            var customer1 = new Customer
            {
                FirstName = "John",
                LastName = "Doe",
                Email = "john.doe@example.com",
                Phone = "555-0100"
            };

            var customer2 = new Customer
            {
                FirstName = "Jane",
                LastName = "Smith",
                Email = "jane.smith@example.com",
                Phone = "555-0200"
            };

            // Create categories
            var electronics = new Category
            {
                Name = "Electronics",
                Description = "Electronic devices and accessories"
            };

            var books = new Category
            {
                Name = "Books",
                Description = "Physical and digital books"
            };

            // Create products
            var laptop = new Product
            {
                Name = "Laptop",
                Description = "High-performance laptop",
                Price = 999.99m,
                StockQuantity = 50,
                Categories = new List<Category> { electronics }
            };

            var novel = new Product
            {
                Name = "Programming Guide",
                Description = "Comprehensive programming guide",
                Price = 49.99m,
                StockQuantity = 100,
                Categories = new List<Category> { books }
            };

            // Create orders
            var order1 = new Order
            {
                OrderDate = DateTime.Now,
                Status = "Processing",
                Customer = customer1,
                OrderItems = new List<OrderItem>
                {
                    new OrderItem
                    {
                        Product = laptop,
                        Quantity = 1,
                        UnitPrice = laptop.Price
                    }
                }
            };

            order1.TotalAmount = order1.OrderItems.Sum(oi => oi.Quantity * oi.UnitPrice);

            // Add to context
            context.Customers.AddRange(customer1, customer2);
            context.Categories.AddRange(electronics, books);
            context.Products.AddRange(laptop, novel);
            context.Orders.Add(order1);

            // Save changes
            context.SaveChanges();
        }
    }
}

What the Seeder Demonstrates

  • Navigation Property Assignment: Shows how to establish relationships by assigning to navigation properties (e.g., Customer = customer1)
  • Collection Initialization: Demonstrates initializing collection navigation properties with related entities
  • Relationship Traversal: Calculates TotalAmount by accessing OrderItems through navigation properties
  • Many-to-Many Setup: Assigns products to categories using collection navigation properties
Testing Strategy: After seeding data, query the database to verify relationships are correctly established. Try accessing navigation properties to confirm Entity Framework Core properly loads related entities.

Entity Relationship Summary

Complete E-Commerce Model Relationships

  • Customer → Orders: One-to-Many (One customer can have many orders)
  • Order → OrderItems: One-to-Many (One order contains many order items)
  • Product → OrderItems: One-to-Many (One product can appear in many order items)
  • Product ↔ Categories: Many-to-Many (Products belong to multiple categories; categories contain multiple products)

Entity Modeling Best Practices

Entity Design Principles

  • Use data annotations for simple validation and display requirements
  • Use Fluent API for complex configurations and relationship definitions
  • Initialize collection navigation properties to empty collections to avoid null references
  • Include both foreign key properties and navigation properties for clarity
  • Use appropriate delete behaviors based on business requirements
  • Apply [Column] attributes for precise decimal types in financial calculations

Naming Conventions

  • Entity classes: Singular nouns (Customer, Order, Product)
  • DbSet properties: Plural nouns (Customers, Orders, Products)
  • Foreign key properties: EntityNameId pattern (CustomerId, ProductId)
  • Navigation properties: Use entity type name (Customer, Order) or collection type (Orders, Products)

Validation Strategy

  • Use [Required] for mandatory fields
  • Use [MaxLength] to prevent data truncation
  • Use [EmailAddress] for email format validation
  • Provide meaningful error messages in validation attributes
  • Consider [Range] for numeric constraints

Key Concepts Summary

Entity Class
A C# class that represents a table in the database. Properties map to columns
Navigation Property
A property that references related entities, enabling object-oriented access to relationships
Foreign Key
A property that stores the primary key value of a related entity, establishing the database relationship
Data Annotations
Attributes applied to entity properties that provide validation rules and database configuration
Fluent API
Code-based configuration approach using method chaining in the OnModelCreating method, providing more options than data annotations
One-to-Many Relationship
A relationship where one entity instance relates to multiple instances of another entity (e.g., one Customer has many Orders)
Many-to-Many Relationship
A relationship where multiple instances of one entity relate to multiple instances of another entity (e.g., Products and Categories)
Linking Entity
An entity that explicitly represents a many-to-many relationship and contains additional properties beyond the foreign keys
Cascade Delete
Automatic deletion of related entities when the parent entity is deleted
