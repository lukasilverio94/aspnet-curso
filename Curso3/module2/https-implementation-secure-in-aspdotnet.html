Configuring HTTPS in ASP.NET Core Applications

A comprehensive guide to implementing secure web applications for development and production environments

Learning Objectives

By the end of this tutorial, you will be able to:

  • Configure HTTPS redirection middleware in ASP.NET Core
  • Enable SSL certificates for secure communications
  • Implement HTTP Strict Transport Security (HSTS) headers
  • Differentiate between development and production HTTPS configurations
  • Troubleshoot common HTTPS endpoint issues

Project Setup

We'll be working with a sample ASP.NET Core application called "SecureWebApp" to demonstrate HTTPS configuration. Open Visual Studio Code and navigate to the project directory.

Opening the Program.cs File

The Program.cs file contains the application's startup configuration. This is where we'll add our HTTPS and security configurations.

Configuring HTTPS Redirection

Step 1: Adding HTTPS Redirection Service

In the services configuration section of Program.cs, locate the builder.Services area and add the HTTPS redirection configuration:

builder.Services.AddHttpsRedirection(options =>
{
    options.RedirectStatusCode = StatusCodes.Status307TemporaryRedirect;
    options.HttpsPort = 5001;
});

Configuration Breakdown:

RedirectStatusCode
Set to Status307TemporaryRedirect, which indicates a temporary redirect that preserves the HTTP method and body during redirection
HttpsPort
Set to 5001, the default HTTPS port used by ASP.NET Core during local development with Kestrel

Port Configuration in Production

In production environments, HTTPS is often handled by reverse proxies like Nginx or IIS. The port configuration may differ from the development setting of 5001. The reverse proxy typically handles SSL termination and forwards requests to your application.

Implementing HTTP Strict Transport Security (HSTS)

Step 2: Adding HSTS Service Configuration

HSTS is a security feature that forces browsers to use HTTPS connections. Add the following configuration to the services section:

builder.Services.AddHsts(options =>
{
    options.IncludeSubDomains = true;
    options.MaxAge = TimeSpan.FromDays(60);
});

HSTS Configuration Options:

IncludeSubDomains
When set to true, the HSTS policy applies to all subdomains of the current domain, providing comprehensive security coverage
MaxAge
Set to 60 days, this determines how long browsers should remember to only access the site via HTTPS. After this period expires, browsers will need to receive the HSTS header again

What is HSTS?

HTTP Strict Transport Security (HSTS) is a web security policy mechanism that helps protect websites against protocol downgrade attacks and cookie hijacking. Once a browser receives the HSTS header, it will automatically convert all HTTP requests to HTTPS for the specified duration, even if the user types "http://" in the address bar.

Configuring Middleware Pipeline

Step 3: Adding HSTS Middleware (Production Only)

Locate the application configuration section after the var app = builder.Build(); statement. Add HSTS middleware conditionally for non-development environments:

if (!app.Environment.IsDevelopment())
{
    app.UseHsts();
}

This ensures HSTS is only enabled in production environments. During development, you typically don't need HSTS as you're working with self-signed certificates on localhost.

Step 4: Adding HTTPS Redirection Middleware

Add the HTTPS redirection middleware to the pipeline. This should come early in the middleware chain:

app.UseHttpsRedirection();

Middleware Order Matters

The HTTPS redirection middleware should be placed early in the pipeline to redirect HTTP requests to HTTPS before other middleware processes them. This ensures all requests are secured from the start of the pipeline.

Complete Middleware Configuration Example

var app = builder.Build();

if (!app.Environment.IsDevelopment())
{
    app.UseHsts();
}

app.UseHttpsRedirection();

// Other middleware follows...
app.UseRouting();
app.UseAuthorization();
app.MapControllers();

Testing the HTTPS Configuration

Step 5: Running the Application

Open the integrated terminal in Visual Studio Code and navigate to the project directory containing the .csproj file:

cd SecureWebApp
dotnet run

Verifying HTTPS Endpoints

When the application starts, the terminal output should display both HTTP and HTTPS endpoints:

Now listening on: http://localhost:5000
Now listening on: https://localhost:5001

Troubleshooting: HTTPS Endpoint Not Appearing

If the HTTPS endpoint doesn't appear in the terminal output, check your launchSettings.json file located in the Properties folder.

Ensure the applicationUrl includes both HTTP and HTTPS URLs separated by a semicolon:

{
  "profiles": {
    "SecureWebApp": {
      "commandName": "Project",
      "applicationUrl": "https://localhost:5001;http://localhost:5000",
      "environmentVariables": {
        "ASPNETCORE_ENVIRONMENT": "Development"
      }
    }
  }
}

After updating launchSettings.json, restart the application to see both endpoints listed.

Key Security Concepts Summary

HTTPS Redirection
Automatically redirects all HTTP requests to HTTPS, ensuring encrypted communication between client and server
SSL/TLS Certificates
Digital certificates that enable encrypted connections. Development uses self-signed certificates, while production requires certificates from trusted Certificate Authorities
HSTS (HTTP Strict Transport Security)
A security header that instructs browsers to only access the site via HTTPS for a specified duration
Status Code 307
Temporary redirect status code that preserves the HTTP method and request body during redirection
Middleware Pipeline
The sequence of components that process HTTP requests and responses. Order is critical for proper security implementation
Environment-Based Configuration
Different security settings for development versus production environments, allowing flexibility during development while maintaining strict security in production

Security Best Practices

Development Environment

  • Use self-signed certificates for local HTTPS testing
  • Avoid enabling HSTS in development to prevent browser caching issues
  • Keep development and production configurations separate

Production Environment

  • Always enable HSTS with appropriate MaxAge values (typically 30-365 days)
  • Include subdomains in HSTS policy when applicable
  • Use certificates from trusted Certificate Authorities
  • Configure reverse proxies (Nginx, IIS) to handle SSL termination
  • Place HTTPS redirection early in the middleware pipeline
  • Regularly update and renew SSL certificates before expiration

Additional Security Headers

Beyond HTTPS and HSTS, consider implementing additional security headers:

  • X-Content-Type-Options: Prevents MIME type sniffing
  • X-Frame-Options: Protects against clickjacking attacks
  • Content-Security-Policy: Controls resource loading to prevent XSS attacks
  • Referrer-Policy: Controls information sent in the Referer header

Conclusion

In this tutorial, you've learned how to configure HTTPS in ASP.NET Core applications for both development and production environments. You've implemented:

  • HTTPS redirection services with proper status codes and port configuration
  • HTTP Strict Transport Security (HSTS) with subdomain inclusion and max-age settings
  • Environment-specific middleware configuration
  • Proper middleware pipeline ordering for security
  • Troubleshooting techniques for HTTPS endpoint issues

These security configurations form the foundation of secure web applications, protecting data in transit and ensuring users connect to your application safely. Always test your HTTPS configuration in both development and production environments to verify proper implementation.
