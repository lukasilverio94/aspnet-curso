.NET Aspire Local Testing and Azure Deployment

Introduction

This tutorial demonstrates how to test your .NET Aspire configuration locally using the built-in dashboard, and then deploy the application to Azure Container Apps using Azure Developer CLI. You'll see automatic service orchestration, distributed tracing, and seamless cloud deployment in action.

Testing .NET Aspire Configuration Locally

Before deploying to the cloud, it's important to test the application locally to ensure all services are properly configured and communicating.

Step 1: Navigate to Root Directory

In the terminal, navigate back to the root directory of your project:

cd ..

Step 2: Run the Application

Start the application using the App Host project:

dotnet run --project ShoppingApp.AppHost
What Happens: .NET Aspire automatically starts all services, assigns ports, and configures networking. Each service receives its own port assignment automatically without manual configuration.

Exploring the .NET Aspire Dashboard

Once the application starts, a dashboard URL appears in the terminal output. Select this URL to open the Aspire dashboard in your browser.

Dashboard Overview

The Aspire dashboard provides real-time monitoring of your distributed application with the following features:

  • Service Status: All services displayed with their current health status
  • Resource Monitoring: View running services like shopping-api and shopping-web
  • Health Indicators: Each service shows "Running" and "Healthy" status
  • Distributed Tracing: Built-in observability for request flows

Viewing Distributed Traces

To explore the distributed tracing capabilities:

  1. Select the Traces tab in the dashboard
  2. Observe how .NET Aspire is prepared to trace requests flowing between services
Built-in Observability: Even without making any requests yet, you can see that .NET Aspire has automatic tracing configured and ready to capture distributed transactions across your microservices.

Stopping the Local Application

When finished testing locally, stop the application in the terminal:

Ctrl+C

Preparing for Azure Deployment

To deploy the .NET Aspire application to Azure, you need to create configuration files that define the deployment pipeline and infrastructure.

Step 1: Create GitHub Actions Deployment Workflow

In the root directory, create a new file named:

azure-deploy.yaml

GitHub Actions Workflow Configuration

name: Deploy to Azure Container Apps

on:
  push:
    branches:
      - main

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Setup .NET
        uses: actions/setup-dotnet@v3
        with:
          dotnet-version: '8.0.x'
      
      - name: Azure Login
        uses: azure/login@v1
        with:
          creds: ${{ secrets.AZURE_CREDENTIALS }}
      
      - name: Deploy to Azure
        run: |
          azd deploy
Purpose: This GitHub Actions workflow automatically builds and deploys your .NET Aspire application to Azure Container Apps whenever you push to the main branch.

Step 2: Create Azure Developer CLI Template

Create another new file in the root directory named:

azd-template.yaml

Azure Developer CLI Template Configuration

name: ShoppingApp
metadata:
  template: aspire-app
services:
  shoppingapp-api:
    project: ./ShoppingApp.API
    language: dotnet
    host: containerapp
  shoppingapp-web:
    project: ./ShoppingApp.Web
    language: dotnet
    host: containerapp
    ingress:
      external: true
      targetPort: 8080
Purpose: This template tells Azure Developer CLI how to deploy your services to Azure Container Apps, including which services need external access. The web application is configured with external ingress so users can access it from the internet.

Deploying with Azure Developer CLI

The Azure Developer CLI (azd) provides a streamlined way to deploy cloud-native applications to Azure.

Step 1: Initialize Azure Deployment

In the terminal, initialize the Azure Developer CLI for your project:

azd init

Initialization Process

The Azure Developer CLI will prompt you with questions:

  1. How to initialize: Select "Scan the current directory"
  2. Confirm settings: Review and confirm the detected configuration
What Happens: The Azure Developer CLI initializes your project for cloud deployment by scanning your application structure and creating the necessary configuration.

Step 2: Deploy to Azure

Once initialization is complete, deploy the application:

azd up

Authentication

You will need to log in to Azure during this process. Follow the authentication prompts to sign in with your Azure credentials.

Subscription Selection

If you have multiple Azure subscriptions, you'll be prompted to select which subscription to use for deployment.

Automated Azure Resource Creation

The Azure Developer CLI automatically creates all necessary Azure resources:

  • Resource Group: A container for all your application resources
  • Container Apps Environment: The hosting environment for your microservices
  • Individual Container Apps: Separate container apps for each service (shopping-api, shopping-web)
  • Application Insights: Monitoring and telemetry for observability
  • Networking: Virtual networks and ingress configuration
  • Scaling Rules: Automatic scaling policies for each service

Verifying the Deployment in Azure

After deployment completes, you can verify and manage your application through the Azure Portal.

Accessing the Azure Portal

Navigate to the Azure Portal and locate your Container Apps resource group. You should see:

  • shopping-web container app
  • shopping-api container app
  • Container Apps Environment
  • Application Insights resource

Examining Container App Details

Select the shopping-web container app to view its configuration:

Container App Features

  • Automatic Scaling: Configured scale rules for handling load
  • Network Setup: Ingress and egress configuration
  • Health Status: Current health probes and status
  • Configuration: Environment variables and settings
  • Revisions: Deployment history and version management
Automatic Configuration: .NET Aspire automatically configured all of these aspects during deployment. You didn't need to manually set up scaling, networking, or health checks.

Testing the Deployed Application

To test your application running in Azure:

  1. In the Container App details, locate the Application URL
  2. Select the URL to open your deployed application
Note: If the container app shows as "Stopped," you may need to restart it from the Azure Portal. Container Apps can automatically stop when idle to save costs, depending on your scaling configuration.

Restarting a Container App

If needed, restart the container app:

  1. Select the container app in the Azure Portal
  2. Select Restart from the toolbar
  3. Wait for the app to reach "Running" status
  4. Access the application URL again

Benefits of .NET Aspire for Cloud Deployment

Development to Production Consistency

The same observability features that work in development automatically carry through to production, providing consistent monitoring and debugging capabilities across all environments.

Key Advantages

Automatic Service Discovery
Services can find and communicate with each other without hardcoded URLs, working seamlessly in both local development and Azure production environments.
Integrated Observability
Built-in distributed tracing, logging, and metrics collection work automatically in development and production. Application Insights captures telemetry without additional configuration.
Automatic Scaling
Azure Container Apps automatically scale your services based on demand, with scaling rules configured by .NET Aspire during deployment.
Simplified Deployment
Azure Developer CLI handles infrastructure provisioning, container building, and deployment with a single command.
Infrastructure as Code
Deployment configuration is stored in YAML files, making it version-controlled, repeatable, and easy to modify.
Zero-Downtime Updates
Container Apps support revision management for blue-green deployments and gradual rollouts.

Conclusion

.NET Aspire transforms traditional ASP.NET Core applications into cloud-native, observable, and easily deployable systems. The framework provides:

  • Local Development Experience: Built-in dashboard with real-time monitoring and distributed tracing
  • Automatic Infrastructure: Service discovery, networking, and container orchestration handled automatically
  • Seamless Deployment: Single-command deployment to Azure with all infrastructure provisioned automatically
  • Production Observability: Same monitoring capabilities in production as in development
  • Cloud-Native Patterns: Automatic scaling, health checks, and resilience built in
Result: Your application now runs successfully in Azure Container Apps with automatic service discovery, integrated observability, and automatic scaling—all configured by .NET Aspire without manual infrastructure setup.
