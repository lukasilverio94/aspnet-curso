How Email Confirmation Works

  1. Token Generation: The system generates a unique confirmation token using GenerateEmailConfirmationTokenAsync
  2. URL Encoding: The token is Base64 URL-encoded for safe transmission in email links
  3. Callback URL Creation: A confirmation URL is created pointing to the ConfirmEmail page with the user ID and token
  4. Email Dispatch: The confirmation email is sent with the callback link embedded
  5. Redirection: Instead of signing in automatically, users are redirected to a confirmation page

Understanding Password Reset Functionality

Forgot Password Implementation

Open the Forgot Password file to examine how password reset tokens are generated:

Open: Areas/Identity/Pages/Account/ForgotPassword.cshtml.cs

Forgot Password OnPostAsync Method

public async Task<IActionResult> OnPostAsync()
{
    if (ModelState.IsValid)
    {
        var user = await _userManager.FindByEmailAsync(Input.Email);
        
        if (user == null || !(await _userManager.IsEmailConfirmedAsync(user)))
        {
            // Don't reveal that the user does not exist or is not confirmed
            return RedirectToPage("./ForgotPasswordConfirmation");
        }
        
        // Generate password reset token
        var code = await _userManager.GeneratePasswordResetTokenAsync(user);
        code = WebEncoders.Base64UrlEncode(Encoding.UTF8.GetBytes(code));
        
        // Create callback URL for password reset
        var callbackUrl = Url.Page(
            "/Account/ResetPassword",
            pageHandler: null,
            values: new { area = "Identity", code },
            protocol: Request.Scheme);
        
        // Send password reset email
        await _emailSender.SendEmailAsync(
            Input.Email,
            "Reset Password",
            $"Please reset your password by <a href='{HtmlEncoder.Default.Encode(callbackUrl)}'>clicking here</a>.");
        
        return RedirectToPage("./ForgotPasswordConfirmation");
    }
    
    return Page();
}

Password Reset Token Generation Process

Step Description
User Lookup System finds the user account by email address
Token Generation GeneratePasswordResetTokenAsync creates a time-limited reset token
URL Encoding Token is Base64 URL-encoded for safe transmission
Callback URL Reset link is created pointing to the ResetPassword page with the token
Email Sending Email with reset link is sent to the user's registered email address

Security Best Practice: Notice that the system doesn't reveal whether a user account exists or if the email is confirmed. This prevents attackers from using the password reset feature to enumerate valid user accounts.

Password Reset Completion

Opening the Reset Password File

Open: Areas/Identity/Pages/Account/ResetPassword.cshtml.cs

Reset Password OnPostAsync Method

Navigate to the OnPostAsync method to see how the actual password reset is handled using the token:

public async Task<IActionResult> OnPostAsync()
{
    if (!ModelState.IsValid)
    {
        return Page();
    }
    
    var user = await _userManager.FindByEmailAsync(Input.Email);
    if (user == null)
    {
        // Don't reveal that the user does not exist
        return RedirectToPage("./ResetPasswordConfirmation");
    }
    
    // Decode the token and reset the password
    var code = Encoding.UTF8.GetString(WebEncoders.Base64UrlDecode(Input.Code));
    var result = await _userManager.ResetPasswordAsync(user, code, Input.Password);
    
    if (result.Succeeded)
    {
        return RedirectToPage("./ResetPasswordConfirmation");
    }
    
    foreach (var error in result.Errors)
    {
        ModelState.AddModelError(string.Empty, error.Description);
    }
    
    return Page();
}

Token Validation and Password Update

The ResetPasswordAsync method performs several critical operations:

  • Token Validation: Verifies the reset token is valid and hasn't been tampered with
  • Expiration Check: Ensures the token hasn't expired (tokens have a default lifetime)
  • Password Update: If validation succeeds, updates the user's password with the new value
  • Token Invalidation: Once used, the token is invalidated to prevent reuse

<script>
    document.getElementById('password').addEventListener('input', function(e) {
        const password = e.target.value;
        const strengthDiv = document.getElementById('password-strength');
        
        let strength = 'Weak';
        let color = 'text-danger';
        
        if (password.length >= 8 && /[A-Z]/.test(password) && 
            /[a-z]/.test(password) && /[0-9]/.test(password)) {
            strength = 'Strong';
            color = 'text-success';
        } else if (password.length >= 6) {
            strength = 'Medium';
            color = 'text-warning';
        }
        
        strengthDiv.innerHTML = `<small class="${color}">Password Strength: ${strength}</small>`;
    });
</script>

Complete Authentication System Workflow

Registration and Email Confirmation Flow

  1. User Registration: User submits registration form with email and password
  2. Account Creation: System creates user account in the database
  3. Token Generation: Confirmation token is generated and encoded
  4. Email Dispatch: Confirmation email with callback link is sent to user
  5. Confirmation Page: User is redirected to page explaining email verification requirement
  6. Email Verification: User clicks link in email to confirm account
  7. Account Activation: Account is marked as confirmed and user can log in

Login Security Flow

  1. Credential Entry: User enters email and password
  2. Account Lookup: System finds user account in database
  3. Password Validation: Password is verified against stored hash
  4. Confirmation Check: System verifies email has been confirmed
  5. Access Decision: Login succeeds only if all checks pass
  6. Error Handling: Appropriate error messages displayed for failures

Password Reset Flow

  1. Reset Request: User enters email on Forgot Password page
  2. Account Verification: System verifies account exists and is confirmed
  3. Token Generation: Time-limited reset token is created
  4. Email Delivery: Reset link with token is sent via email
  5. Link Click: User clicks link to access Reset Password page
  6. New Password Entry: User provides new password
  7. Token Validation: System validates token hasn't expired
  8. Password Update: If valid, password is updated in database
  9. Token Invalidation: Used token is invalidated to prevent reuse

Security Features Implemented

Email Verification

Prevents unauthorized account creation and ensures users have access to their registered email addresses.

Token-Based Operations

Uses cryptographically secure tokens for email confirmation and password reset, with built-in expiration.

Information Disclosure Prevention

Doesn't reveal whether accounts exist when users attempt password reset or login, preventing account enumeration attacks.

Secure Password Storage

ASP.NET Core Identity automatically hashes passwords using industry-standard algorithms before storing them.

Account Lockout Protection

Built-in protection against brute force attacks through configurable account lockout policies.

HTTPS Enforcement

Callback URLs use the request scheme, ensuring HTTPS is used in production environments for secure token transmission.

Key Concepts Summary

Email Confirmation Token
A cryptographically secure, time-limited token used to verify that users have access to their registered email address. Generated using GenerateEmailConfirmationTokenAsync and validated when users click the confirmation link.
Password Reset Token
A secure, time-limited token generated for password reset operations. Created with GeneratePasswordResetTokenAsync and used to authenticate password change requests without requiring the current password.
OnPostAsync Method
The ASP.NET Core Razor Pages method that handles form submissions. Contains the server-side logic for processing registration, login, and password reset operations.
Callback URL
A URL embedded in confirmation and reset emails that includes the necessary tokens and parameters to complete the verification or reset process. Uses URL encoding to ensure special characters are properly transmitted.
Validation Summary
An ASP.NET Core tag helper that displays validation errors from the ModelState. Shows user-friendly error messages for failed registration, login, or password reset attempts.
RequireConfirmedAccount
An Identity option that prevents users from signing in until their email address has been confirmed, adding an extra layer of security to the authentication process.

  • Unauthorized account creation without valid email access
  • Account enumeration through login or password reset features
  • Brute force password attacks
  • Password reset token reuse or manipulation

Production Considerations: Before deploying to production, ensure that:

  • HTTPS is enforced for all authentication pages
  • Email templates are professionally designed and branded
