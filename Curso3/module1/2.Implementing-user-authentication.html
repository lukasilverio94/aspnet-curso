Building Authentication with ASP.NET Core Identity

Complete guide to implementing user registration, login, email confirmation, and password reset

Demonstration Overview

This demonstration shows how to build a complete authentication system using ASP.NET Core Identity with the following features:

  • User registration with account creation
  • Login functionality with security validation
  • Email confirmation for account verification
  • Password reset capabilities
  • Secure and user-friendly authentication experience

Goal: By the end of this demonstration, you'll observe how all authentication components work together to create a comprehensive, secure identity management system.

Creating a New ASP.NET Core Project with Identity

Opening the Terminal

Step 1: Open the terminal in Visual Studio Code
Step 2: Open a new terminal window for a clean workspace
Step 3: Navigate to your code folder

Creating the Project

Use the .NET CLI to create a new web application with built-in identity authentication support:

dotnet new webapp --auth Individual -o AuthenticationDemo

Command Breakdown

  • dotnet new webapp - Creates a new ASP.NET Core web application
  • --auth Individual - Configures the project with individual user authentication
  • -o AuthenticationDemo - Sets the output directory and project name

Result: This command creates a project with ASP.NET Core Identity already configured, including the necessary database context, identity services, and default UI pages.

Navigating to the Project

After the project is created successfully, navigate into the project directory:

cd AuthenticationDemo

Opening in Visual Studio Code

Open the project in VS Code using the following command:

code .

This opens the AuthenticationDemo project in Visual Studio Code, ready for customization.

Configuring Email Settings for Account Confirmation

Opening Configuration File

Open the appsettings.json file to add email configuration.

Adding Email Settings

Add an email configuration section after the logging section:

{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "EmailSettings": {
    "SmtpServer": "smtp.gmail.com",
    "SmtpPort": 587,
    "SenderName": "Authentication Demo",
    "SenderEmail": "your-email@gmail.com",
    "Username": "your-email@gmail.com",
    "Password": "your-app-password"
  },
  "AllowedHosts": "*"
}

Configuration Properties

Property Description
SmtpServer Gmail SMTP server address
SmtpPort Port number for SMTP communication (587 for TLS)
SenderName Display name for outgoing emails
SenderEmail Email address that sends confirmation messages
Username SMTP authentication username
Password SMTP authentication password (use app-specific password)

Security Note: For Gmail, use an app-specific password rather than your regular account password. Never commit actual credentials to source control—use environment variables or secrets management in production.

Creating an Email Service

Creating the Service File

Step 1: Right-click on the project root
Step 2: Select "New File" from the context menu
Step 3: Name the file EmailService.cs

Implementing the Email Service

using System.Net;
using System.Net.Mail;
using Microsoft.Extensions.Configuration;

namespace AuthenticationDemo
{
    public class EmailService
    {
        private readonly IConfiguration _configuration;

        public EmailService(IConfiguration configuration)
        {
            _configuration = configuration;
        }

        public async Task SendEmailAsync(string toEmail, string subject, string body)
        {
            var emailSettings = _configuration.GetSection("EmailSettings");
            
            var smtpServer = emailSettings["SmtpServer"];
            var smtpPort = int.Parse(emailSettings["SmtpPort"]);
            var senderEmail = emailSettings["SenderEmail"];
            var senderName = emailSettings["SenderName"];
            var username = emailSettings["Username"];
            var password = emailSettings["Password"];

            var mailMessage = new MailMessage
            {
                From = new MailAddress(senderEmail, senderName),
                Subject = subject,
                Body = body,
                IsBodyHtml = true
            };
            
            mailMessage.To.Add(toEmail);

            using var smtpClient = new SmtpClient(smtpServer, smtpPort)
            {
                Credentials = new NetworkCredential(username, password),
                EnableSsl = true
            };

            await smtpClient.SendMailAsync(mailMessage);
        }
    }
}

Service Implementation Details

  • Dependency Injection: Uses IConfiguration to access app settings
  • Configuration Binding: Reads email settings from the "EmailSettings" section
  • SMTP Setup: Configures SMTP client with server, port, and credentials
  • Email Composition: Creates and sends HTML email messages
  • Async Operation: Uses async/await for non-blocking email sending

How It Works: This service handles sending emails using the SMTP configuration we added to appsettings.json. The configuration is injected through dependency injection, allowing the service to reference settings by accessing the "EmailSettings" section.

Scaffolding Identity Pages for Customization

Why Scaffold Identity Pages?

Scaffolding generates customizable versions of the default identity pages, allowing you to tailor the registration flow and other authentication processes to your specific requirements.

Opening the Terminal

Open a new terminal window in Visual Studio Code

Installing the Identity UI Package

First, ensure you have the Identity UI package installed:

dotnet add package Microsoft.AspNetCore.Identity.UI

Running the Scaffolding Command

Use the ASP.NET code generator to scaffold specific identity pages:

dotnet aspnet-codegenerator identity -dc AuthenticationDemo.Data.ApplicationDbContext --files "Account.Register;Account.Login;Account.ConfirmEmail;Account.ForgotPassword;Account.ResetPassword"

Command Breakdown

Parameter Purpose
aspnet-codegenerator identity Invokes the identity scaffolding tool
-dc ApplicationDbContext Specifies the database context to use
--files Lists specific pages to scaffold (semicolon-separated)

Scaffolded Pages

  • Account.Register - User registration page
  • Account.Login - User login page
  • Account.ConfirmEmail - Email confirmation page
  • Account.ForgotPassword - Password recovery initiation page
  • Account.ResetPassword - Password reset page

Result of Scaffolding

Generated Files: This generates customizable versions of the key identity pages in the Areas/Identity/Pages/Account folder. You can now modify these pages to customize the user experience, add additional validation, change styling, or integrate with other services.

Complete Authentication Flow

User Registration Process

  1. User submits registration form with email and password
  2. ASP.NET Core Identity validates the input data
  3. System creates new user account in the database
  4. Email confirmation token is generated
  5. EmailService sends confirmation email with link
  6. User receives email and clicks confirmation link
  7. Account is confirmed and user can log in

Login Process

  1. User provides email and password credentials
  2. Identity system validates credentials against database
  3. If account requires confirmation, check confirmation status
  4. Generate authentication cookie upon successful login
  5. Redirect user to authorized area of application

Password Reset Flow

  1. User navigates to "Forgot Password" page
  2. User enters registered email address
  3. System generates password reset token
  4. EmailService sends reset link to user's email
  5. User clicks link and provides new password
  6. System validates token and updates password
  7. User can log in with new credentials

Key Concepts Summary

ASP.NET Core Identity
A membership system that adds login functionality to ASP.NET Core applications, including user registration, authentication, authorization, and password management.
Scaffolding
The process of generating customizable code files from templates, allowing developers to modify default implementations to meet specific requirements.
Email Confirmation
A security feature that verifies user email addresses by sending a confirmation token via email, ensuring users have access to their registered email accounts.
ApplicationDbContext
The Entity Framework database context that manages identity-related data including users, roles, claims, and authentication tokens.
SMTP Configuration
Settings that enable the application to send emails through a mail server, including server address, port, credentials, and encryption settings.
Dependency Injection
A design pattern where dependencies (like configuration or services) are provided to classes rather than created internally, improving testability and maintainability.
