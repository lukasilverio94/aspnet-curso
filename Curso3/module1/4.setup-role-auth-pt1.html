Implementing Role-Based Authorization in ASP.NET Core

Introduction

This tutorial demonstrates how to implement role-based authorization in an ASP.NET Core application. You'll learn how to create user roles, assign users to those roles, and protect your controllers and actions so that only authorized users can access them.

Setting Up User Roles

The first step in implementing role-based authorization is to create a custom user class that extends ASP.NET Core Identity's user management capabilities.

Creating the Application User Class

File: Models/ApplicationUser.cs

Create a new file in the Models folder named ApplicationUser.cs:

using Microsoft.AspNetCore.Identity;

namespace YourApplication.Models
{
    public class ApplicationUser : IdentityUser
    {
        public string FirstName { get; set; }
        public string LastName { get; set; }
    }
}
Key Points:
  • This class extends IdentityUser, which provides built-in support for roles and claims
  • Additional properties like FirstName and LastName can be added for extra user information
  • The IdentityUser base class includes properties for email, username, password hash, and role associations

Creating the Database Context

The database context manages the connection between your application and the database, including all identity-related tables.

Setting Up ApplicationDbContext

File: Data/ApplicationDbContext.cs

Create a new file in the Data folder named ApplicationDbContext.cs:

using Microsoft.AspNetCore.Identity.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore;
using YourApplication.Models;

namespace YourApplication.Data
{
    public class ApplicationDbContext : IdentityDbContext<ApplicationUser>
    {
        public ApplicationDbContext(DbContextOptions<ApplicationDbContext> options)
            : base(options)
        {
        }
    }
}
What This Does:
  • Inherits from IdentityDbContext<ApplicationUser> with your custom user class
  • Automatically sets up all necessary tables for user management, roles, and claims
  • Provides database access for identity operations like user creation, role assignment, and authentication

Configuring Services in Program.cs

The services must be configured to enable Entity Framework, ASP.NET Core Identity, and role-based authorization.

Database and Identity Configuration

File: Program.cs

Locate the services configuration section and add the following:

// Add DbContext with SQL Server
builder.Services.AddDbContext<ApplicationDbContext>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection")));

// Configure ASP.NET Core Identity
builder.Services.AddIdentity<ApplicationUser, IdentityRole>(options =>
{
    // Password requirements
    options.Password.RequireDigit = true;
    options.Password.RequireLowercase = true;
    options.Password.RequireUppercase = true;
    options.Password.RequireNonAlphanumeric = false;
    options.Password.RequiredLength = 6;
})
.AddEntityFrameworkStores<ApplicationDbContext>()
.AddDefaultTokenProviders();

Configuration Breakdown:

AddDbContext
Configures Entity Framework Core with SQL Server as the database provider
AddIdentity<ApplicationUser, IdentityRole>
Sets up ASP.NET Core Identity with your custom ApplicationUser class and the default IdentityRole for role management
Password Options
Defines password complexity requirements for user accounts
AddEntityFrameworkStores
Connects Identity to your database context for data persistence
AddDefaultTokenProviders
Enables token generation for password resets and email confirmation

Adding Authentication and Authorization Middleware

Middleware components must be added in the correct order for proper security functionality.

Middleware Setup

In the middleware configuration section of Program.cs, add the following before the authorization middleware:

// Other middleware...

app.UseAuthentication();  // Must come before UseAuthorization
app.UseAuthorization();

// Other middleware...
Order Matters: The middleware components must be in the correct order:
  1. UseAuthentication() - Identifies who the user is
  2. UseAuthorization() - Checks if the user has permission to access resources

Authentication must come before authorization so the system can identify users before checking their permissions.

Creating an Admin Controller

This controller demonstrates class-level role-based authorization, where all actions require admin privileges.

AdminController Implementation

File: Controllers/AdminController.cs

using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;

namespace YourApplication.Controllers
{
    [Authorize(Roles = "Admin")]
    public class AdminController : Controller
    {
        public IActionResult Index()
        {
            return View();
        }

        public IActionResult ManageUsers()
        {
            return View();
        }
    }
}

Authorization Behavior

Class-Level Authorization

The [Authorize(Roles = "Admin")] attribute at the class level means:

  • All actions in this controller require the user to be authenticated
  • The authenticated user must be in the "Admin" role
  • Any user not in the Admin role will receive a 403 Forbidden response
  • Unauthenticated users will be redirected to the login page

Controller Actions

Index()
Main admin dashboard - requires Admin role (inherited from class-level attribute)
ManageUsers()
User management functionality - requires Admin role (inherited from class-level attribute)

Creating a Manager Controller

This controller demonstrates action-level authorization with multiple roles, providing more granular control over access.

ManagerController Implementation

File: Controllers/ManagerController.cs

using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;

namespace YourApplication.Controllers
{
    public class ManagerController : Controller
    {
        [Authorize(Roles = "Manager,Admin")]
        public IActionResult Dashboard()
        {
            return View();
        }

        [Authorize(Roles = "Admin")]
        public IActionResult AdminOnly()
        {
            return View();
        }

        public IActionResult PublicAction()
        {
            return View();
        }
    }
}

Action-Level Authorization

Multiple Authorization Levels

This controller demonstrates different authorization approaches:

1. Multiple Roles (Dashboard action)

[Authorize(Roles = "Manager,Admin")]

  • Allows both Manager and Admin roles
  • Uses a comma-separated list of role names
  • User must be in at least one of the specified roles
2. Single Role (AdminOnly action)

[Authorize(Roles = "Admin")]

  • Requires only the Admin role
  • Managers cannot access this action
  • Demonstrates action-level override of controller settings
3. No Authorization (PublicAction)

No [Authorize] attribute

  • No authentication or authorization required
  • Accessible to all users, including anonymous visitors
  • Useful for public-facing features within a controller

Class-Level vs Action-Level Authorization

When to Use Each Approach

Class-Level Authorization

Use When:
  • All actions in the controller require the same role(s)
  • The controller represents a specific administrative area
  • You want consistent security across all endpoints
Example: AdminController where all actions require Admin role

Action-Level Authorization

Use When:
  • Different actions require different authorization levels
  • Some actions are public while others are restricted
  • You need granular control over access permissions
Example: ManagerController with mixed public and restricted actions

Combining Both Approaches

You can combine class-level and action-level authorization:

[Authorize] // Class-level: requires authentication
public class MixedController : Controller
{
    public IActionResult Index() 
    { 
        // Requires authentication (from class)
        return View(); 
    }

    [Authorize(Roles = "Admin")] // Action-level: requires Admin role
    public IActionResult AdminAction() 
    { 
        return View(); 
    }

    [AllowAnonymous] // Overrides class-level authorization
    public IActionResult Public() 
    { 
        return View(); 
    }
}

Key Authorization Concepts

Authentication
The process of identifying who the user is. This happens through login credentials, tokens, or other identity verification methods.
Authorization
The process of determining what an authenticated user is allowed to do. This is where roles and permissions come into play.
Role
A named group that defines a set of permissions. Users can be assigned to one or more roles (e.g., Admin, Manager, User).
[Authorize] Attribute
A filter that restricts access to controllers or actions based on authentication and role requirements.
IdentityUser
The base class provided by ASP.NET Core Identity for user accounts. It includes properties for username, email, password, and role associations.
IdentityRole
The default role class that represents user roles in the system.
IdentityDbContext
A specialized Entity Framework DbContext that includes all tables needed for ASP.NET Core Identity (users, roles, claims, etc.).
[AllowAnonymous] Attribute
Overrides authorization requirements, allowing unauthenticated access to specific actions even when the controller requires authentication.

Implementation Summary

To implement role-based authorization in ASP.NET Core:

  1. Create ApplicationUser Class: Extend IdentityUser with custom properties
  2. Create ApplicationDbContext: Inherit from IdentityDbContext to manage identity data
  3. Configure Services: Add database context, Identity services, and password requirements in Program.cs
  4. Add Middleware: Include UseAuthentication() before UseAuthorization() in the request pipeline
  5. Apply Authorization: Use [Authorize(Roles = "RoleName")] attributes on controllers or actions
  6. Create Roles: Programmatically create roles and assign users to them (covered in role management tutorials)
  7. Test Security: Verify that users without proper roles cannot access protected resources

Next Steps

After implementing basic role-based authorization, consider these additional topics:

  • Role Management: Create interfaces for administrators to create roles and assign users
  • Claims-Based Authorization: Implement more granular permissions using claims
  • Policy-Based Authorization: Define custom authorization policies for complex scenarios
  • Resource-Based Authorization: Authorize based on the specific resource being accessed
  • Custom Authorization Handlers: Create sophisticated authorization logic beyond simple role checks
  • Two-Factor Authentication: Add an extra layer of security to user accounts

Conclusion

Role-based authorization is a fundamental security feature in ASP.NET Core applications. By creating custom user classes, configuring ASP.NET Core Identity, and applying authorization attributes strategically, you can:

  • Control access to different parts of your application
  • Protect sensitive functionality from unauthorized users
  • Implement sophisticated permission systems
  • Maintain clear separation between user privilege levels

The combination of class-level and action-level authorization provides flexibility to secure your application according to your specific business requirements.
