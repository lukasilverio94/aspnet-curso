Configuring Database and Running Migrations for ASP.NET Core Identity

Introduction

This tutorial completes the ASP.NET Core Identity integration by configuring the database connection string, creating the initial migration, applying it to the database, and testing the authentication system. By the end, you'll have a fully functional user registration and login system.

Learning Objectives

  • Configure database connection strings in appsettings.json
  • Install Entity Framework Core design-time tools
  • Create and apply database migrations
  • Verify database creation and table structure
  • Test the Identity registration system

Configuring the Connection String

Step 1: Open appsettings.json

  1. In the Project Explorer, locate and click on appsettings.json
  2. The file will open in the editor

Step 2: Add Connection String Configuration

Add the connection string element before the logging section:

{
  "ConnectionStrings": {
    "DefaultConnection": "Data Source=app.db"
  },
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*"
}
What This Does:

This connection string tells Entity Framework to create a SQLite database file named app.db in your project directory. The Data Source parameter specifies the database file location.

Step 3: Save Your Changes

Save the appsettings.json file before proceeding to ensure your configuration changes are preserved.

Creating the Database Migration

Understanding Migrations

Migrations are Entity Framework's way of tracking and applying database schema changes. The initial migration creates all the Identity-related tables needed for user management.

Step 1: Navigate to Terminal

Return to your terminal window in Visual Studio Code.

Step 2: Run the Migration Command

dotnet ef migrations add InitialCreate
Troubleshooting: Missing Design Package

If you encounter an error about the Entity Framework Core Design package not being referenced, you need to install it first:

dotnet add package Microsoft.EntityFrameworkCore.Design -v 8

After successfully installing the design package, retry the migration command:

dotnet ef migrations add InitialCreate
Success Indicators:
  • The command completes without errors
  • A new Migrations folder appears in your project
  • The migration files contain the database schema code

What Happens During Migration Creation

Entity Framework generates code that represents your database schema, including:

  • User tables for storing account information
  • Role tables for authorization
  • Claims tables for additional user attributes
  • Relationship definitions between tables

Applying the Migration to the Database

Step 1: Run Database Update Command

With the migration successfully created, apply it to create the actual database:

dotnet ef database update

What Happens During Database Update

Entity Framework executes the migration code to create your database and tables. You'll see SQL commands being executed for:

  • Creating the database file
  • Setting up user identity tables
  • Creating roles tables
  • Establishing claims tables
  • Defining relationships between all tables
Verification:

After the command completes successfully, you'll notice a new app.db file in your project root directory. This SQLite database file contains all of your Identity tables.

Database File Note:

While the app.db file is created and visible in your project, you don't need to open it directly. Entity Framework manages all database interactions through your code.

Testing Your Application

Step 1: Run the Application

dotnet run

The application will start up and display the localhost URL where it's running, typically something like:

Now listening on: https://localhost:5277

Step 2: Navigate to Your Application

  1. Open your web browser
  2. Enter the localhost URL from the terminal (e.g., https://localhost:5277)
  3. Your application should load normally
Success Indicator:

If your application loads without errors, the Identity system has been successfully integrated into your application.

Step 3: Test User Registration

Even though UI links haven't been added yet, you can test the registration functionality by navigating directly to the Identity pages.

Navigate to the registration page by appending /Identity/Account/Register to your localhost URL:

https://localhost:5277/Identity/Account/Register
What You Should See:

The Identity registration page should load, displaying form fields for email, password, and password confirmation. This confirms that your Identity system integration was successful and is functioning properly.

What You've Accomplished

Congratulations! You've successfully integrated ASP.NET Core Identity into your application. Here's what you've completed:

  • Installed Required Packages: Added all necessary NuGet packages for Identity and Entity Framework
  • Created Database Context: Set up the ApplicationDbContext to manage Identity data
  • Configured Services and Middleware: Registered Identity services and authentication middleware in your application pipeline
  • Set Up Connection String: Configured the database connection in appsettings.json
  • Created Initial Migration: Generated the database schema code for Identity tables
  • Applied Migration: Created the actual database with all Identity tables
  • Tested the System: Verified that registration functionality works correctly

Next Steps

Now that your authentication system is set up, you can:

  1. Add login and registration links to your application's navigation
  2. Customize the Identity UI pages to match your application's branding
  3. Implement role-based authorization
  4. Add email confirmation for new registrations
  5. Configure two-factor authentication for enhanced security

Key Concepts Summary

Connection String
A configuration setting that specifies how to connect to a database, including the database type, location, and credentials
Migration
A versioned set of changes to your database schema that can be applied or rolled back, allowing for controlled database evolution
Entity Framework Design Tools
Command-line tools that enable migration creation and database updates during development
SQLite Database
A lightweight, file-based database system ideal for development and small to medium applications
Identity Tables
Database tables that store user accounts, passwords, roles, claims, and authentication-related information

Common Issues and Solutions

Migration Command Fails

Problem: Error about missing Entity Framework Core Design package
Solution: Install the design package: dotnet add package Microsoft.EntityFrameworkCore.Design

Database Update Fails

Problem: Error during database update
Solution: Ensure your connection string is correct and you have write permissions in the project directory

Registration Page Not Found

Problem: 404 error when navigating to /Identity/Account/Register
Solution: Verify that you've added the Identity UI package and configured MapRazorPages() in your middleware

Conclusion

Your application now has a complete, production-ready authentication system with:

  • Secure user registration with password hashing
  • Login functionality with session management
  • Database-backed user storage
  • Pre-built UI pages for common authentication workflows
  • A foundation for implementing advanced security features

This Identity integration provides enterprise-grade security and user management capabilities that you can extend and customize to meet your specific application requirements.
