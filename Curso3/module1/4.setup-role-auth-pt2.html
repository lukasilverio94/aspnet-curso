Role Management and Testing in ASP.NET Core

Introduction

This tutorial demonstrates how to create role management functionality in ASP.NET Core, including creating roles, assigning users to roles, and testing the role-based authorization system. You'll also learn how to troubleshoot common errors that occur during implementation.

Creating the Account Controller

The Account Controller manages user registration, role creation, and role assignment functionality.

AccountController Implementation

File: Controllers/AccountController.cs

using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Identity;
using Microsoft.AspNetCore.Mvc;
using YourApplication.Models;

namespace YourApplication.Controllers
{
    public class AccountController : Controller
    {
        private readonly UserManager<ApplicationUser> _userManager;
        private readonly RoleManager<IdentityRole> _roleManager;

        public AccountController(
            UserManager<ApplicationUser> userManager,
            RoleManager<IdentityRole> roleManager)
        {
            _userManager = userManager;
            _roleManager = roleManager;
        }

        [Authorize(Roles = "Admin")]
        public async Task<IActionResult> CreateRoles()
        {
            // Create Admin role
            if (!await _roleManager.RoleExistsAsync("Admin"))
            {
                await _roleManager.CreateAsync(new IdentityRole("Admin"));
            }

            // Create Manager role
            if (!await _roleManager.RoleExistsAsync("Manager"))
            {
                await _roleManager.CreateAsync(new IdentityRole("Manager"));
            }

            // Create User role
            if (!await _roleManager.RoleExistsAsync("User"))
            {
                await _roleManager.CreateAsync(new IdentityRole("User"));
            }

            return View();
        }

        [Authorize(Roles = "Admin")]
        public async Task<IActionResult> AssignRole(string userId, string roleName)
        {
            var user = await _userManager.FindByIdAsync(userId);
            
            if (user != null && await _roleManager.RoleExistsAsync(roleName))
            {
                await _userManager.AddToRoleAsync(user, roleName);
            }

            return RedirectToAction("Index");
        }
    }
}

Controller Components Explained

Dependency Injection

The constructor injects two key services:

UserManager<ApplicationUser>
Manages user accounts - creating users, finding users by ID, and assigning roles to users
RoleManager<IdentityRole>
Manages roles - creating roles, checking if roles exist, and deleting roles

CreateRoles Method

Purpose: Creates the three basic roles in the system
  • Admin: Full administrative access to all features
  • Manager: Mid-level access for management functions
  • User: Basic user access to standard features

The method checks if each role exists before creating it to avoid duplicate role errors. This action requires the Admin role to execute.

AssignRole Method

Purpose: Assigns a specific user to a specific role

Parameters:

  • userId: The unique identifier of the user
  • roleName: The name of the role to assign

The method finds the user by ID, verifies the role exists, and then adds the user to that role. This action also requires the Admin role.

Creating Database Migrations

Entity Framework migrations create and update the database schema to support Identity tables.

Step 1: Add Migration

Open the terminal and create a new migration:

dotnet ef migrations add InitialCreate

This command generates migration files that define the database schema changes, including tables for:

  • AspNetUsers (user accounts)
  • AspNetRoles (role definitions)
  • AspNetUserRoles (user-role assignments)
  • AspNetUserClaims (user claims)
  • AspNetRoleClaims (role claims)

Step 2: Update Database

Apply the migration to create the database:

dotnet ef database update
Result: The database has been created with all the necessary Identity tables for users, roles, and user-role relationships.

Testing Role-Based Authorization

After setting up the database, test the application to verify that role-based authorization is working correctly.

Running the Application

Start the application from the terminal:

dotnet run

Testing Authorization Behavior

Once the application is running, test the authorization system by navigating to protected routes.

Test 1: Accessing Admin Controller Without Authentication

Navigate to: /admin

Expected Behavior: The application redirects to the login page because the AdminController requires the Admin role, and you are not currently authenticated.

This is the correct behavior - unauthenticated users cannot access protected resources and are automatically redirected to login.

Test 2: Accessing Role Creation Without Admin Role

Navigate to: /account/createroles

Expected Behavior: The application redirects to the login page because the CreateRoles action requires the Admin role authorization.

Even after logging in, users without the Admin role will receive a 403 Forbidden error when trying to access this action.

Troubleshooting Common Errors

During implementation and testing, you may encounter several common errors. Here's how to resolve them.

Error 1: Stray MapRazorPages Call

Error Message: Build error on line 47 in Program.cs

Cause: An extra app.MapRazorPages() call exists in the middleware configuration

Solution

File: Program.cs

// Remove this line if it appears twice:
// app.MapRazorPages(); // DELETE this duplicate

// Keep only the necessary routing:
app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");

After removing the duplicate line, save the file and rebuild the application.

Error 2: IdentityUser Type Mismatch in Views

Error Message: Type mismatch error in _LoginPartial.cshtml

Cause: The view is using IdentityUser instead of your custom ApplicationUser class

Solution

File: Views/Shared/_LoginPartial.cshtml

@using Microsoft.AspNetCore.Identity
@using YourApplication.Models
@inject SignInManager<ApplicationUser> SignInManager
@inject UserManager<ApplicationUser> UserManager
@inject RoleManager<IdentityRole> RoleManager

@if (SignInManager.IsSignedIn(User))
{
    <form class="form-inline" asp-area="" asp-controller="Account" asp-action="Logout">
        <button type="submit" class="nav-link btn btn-link">Logout</button>
    </form>
}
else
{
    <a class="nav-link" asp-area="" asp-controller="Account" asp-action="Register">Register</a>
    <a class="nav-link" asp-area="" asp-controller="Account" asp-action="Login">Login</a>
}
Key Changes:
  • Change IdentityUser to ApplicationUser in all type parameters
  • Add @using YourApplication.Models to import your custom user class
  • Inject RoleManager<IdentityRole> for role management functionality

Error 3: Missing Route Configuration

Symptom: 404 errors when navigating to Admin or Account controllers

Cause: Routes are not properly configured in Program.cs

Solution

File: Program.cs

app.MapControllerRoute(
    name: "admin",
    pattern: "admin/{action=Index}/{id?}",
    defaults: new { controller = "Admin" });

app.MapControllerRoute(
    name: "account",
    pattern: "account/{action=Index}/{id?}",
    defaults: new { controller = "Account" });

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");

Save the Program.cs file, rebuild the application, and restart it.

General Troubleshooting Steps

When You Encounter Errors:

  1. Read the error message carefully - it usually indicates the file and line number
  2. Check file locations - ensure using statements match your project structure
  3. Verify type consistency - use ApplicationUser instead of IdentityUser throughout
  4. Clean and rebuild - sometimes cached build artifacts cause issues
  5. Restart the application - changes to Program.cs require a restart

Complete Testing Workflow

Step-by-Step Testing Process

  1. Build the application: dotnet build
  2. Run the application: dotnet run
  3. Open browser: Navigate to http://localhost:5000 (or the displayed URL)
  4. Test unauthenticated access: Try to access /admin - should redirect to login
  5. Create roles: Navigate to /account/createroles (after logging in as Admin)
  6. Verify roles created: Check the database AspNetRoles table
  7. Assign roles to users: Use the AssignRole action or create an admin interface
  8. Test role-based access: Log in with different role accounts and verify access

Key Components of Role Management

Authorization Levels

Controller-Level Authorization
Applying [Authorize(Roles = "RoleName")] at the class level protects all actions in that controller. Used for AdminController where all actions require admin privileges.
Action-Level Authorization
Applying authorization attributes to individual actions allows for granular control. Used for controllers with mixed access requirements.
No Authorization
Actions without authorization attributes are accessible to all users, including anonymous visitors.

Role Management Services

UserManager<ApplicationUser>
Provides methods for managing users:
  • CreateAsync() - Create new users
  • FindByIdAsync() - Find users by ID
  • FindByEmailAsync() - Find users by email
  • AddToRoleAsync() - Assign users to roles
  • RemoveFromRoleAsync() - Remove users from roles
  • IsInRoleAsync() - Check if user is in a specific role
RoleManager<IdentityRole>
Provides methods for managing roles:
  • CreateAsync() - Create new roles
  • RoleExistsAsync() - Check if a role exists
  • DeleteAsync() - Delete roles
  • FindByNameAsync() - Find roles by name

Key Takeaways

  1. Configure Identity Services: Set up ASP.NET Core Identity in Program.cs with your custom ApplicationUser class
  2. Apply Authorization Strategically: Use controller-level authorization for blanket protection or action-level for granular control
  3. Manage Roles Programmatically: Use RoleManager to create roles and UserManager to assign users
  4. Test Thoroughly: Verify that unauthorized users cannot access protected resources
  5. Plan for Production: Implement additional features like registration, login, and admin interfaces for real-world use

Role-based authorization is a fundamental security feature that protects your application by ensuring users can only access the features and data appropriate for their role. Combined with proper authentication and additional security measures, it provides a robust foundation for secure ASP.NET Core applications.
