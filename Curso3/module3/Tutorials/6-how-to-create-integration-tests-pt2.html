Testing complete workflows from HTTP requests to database operations

Creating Your First Integration Test

Testing the GET Endpoint

Create a test method to verify that the GET products endpoint returns a success status code:

[Fact]
public async Task GetProducts_ReturnsSuccessStatusCode()
{
    // Act
    var response = await _client.GetAsync("/api/products");
    
    // Assert
    response.EnsureSuccessStatusCode();
}

Understanding the Test Components

[Fact] Attribute

[Fact]

Marks this method as an xUnit test that takes no parameters and will be executed by the test runner.

Making the HTTP Request

var response = await _client.GetAsync("/api/products");

What Happens Here: This sends a real HTTP GET request through your application's complete middleware pipeline:

  1. The request passes through routing middleware
  2. Reaches the ProductsController
  3. Executes the GetProducts action method
  4. Queries the in-memory database
  5. Serializes the results to JSON
  6. Returns the HTTP response

This tests the entire request/response cycle, not just isolated components.

Asserting Success

response.EnsureSuccessStatusCode();

EnsureSuccessStatusCode(): This method:

  • Verifies the status code is in the 2xx range (200-299)
  • Throws an exception if the status code indicates an error
  • Makes the test fail automatically for 4xx or 5xx responses
  • Provides clear error messages when the assertion fails

Testing the POST Endpoint

Creating a POST Test Method

Create a test to verify that the POST endpoint successfully creates a new product:

[Fact]
public async Task CreateProduct_WithValidData_ReturnsCreatedResponse()
{
    // Arrange
    var newProduct = new
    {
        Name = "Test Product",
        Price = 29.99
    };
    
    // Act
    var response = await _client.PostAsJsonAsync("/api/products", newProduct);
    
    // Assert
    Assert.Equal(HttpStatusCode.Created, response.StatusCode);
    
    var createdProduct = await response.Content.ReadFromJsonAsync<Product>();
    Assert.NotNull(createdProduct);
    Assert.Equal("Test Product", createdProduct.Name);
    Assert.Equal(29.99m, createdProduct.Price);
}

Understanding JSON Serialization

Sending JSON Data

PostAsJsonAsync Method: This convenience method:

  • Automatically serializes the object to JSON
  • Sets the Content-Type header to application/json
  • Sends the JSON in the request body
  • Returns the HTTP response

Alternative Manual Approach:

var jsonString = JsonSerializer.Serialize(newProduct);
var content = new StringContent(jsonString, Encoding.UTF8, "application/json");
var response = await _client.PostAsync("/api/products", content);

The PostAsJsonAsync method handles all of this automatically.

What This Test Validates

Complete Workflow Testing: This test verifies:

  1. HTTP Routing: Request reaches the correct controller action
  2. Model Binding: JSON is deserialized to Product object
  3. Validation: Data annotations are enforced (if present)
  4. Business Logic: Controller properly processes the request
  5. Database Operations: Product is added to the database
  6. Response Creation: 201 Created status is returned
  7. Response Data: Created product is included in response body

Multiple Assertions

// Assert status code
Assert.Equal(HttpStatusCode.Created, response.StatusCode);

// Read and deserialize response content
var createdProduct = await response.Content.ReadFromJsonAsync<Product>();

// Verify response data
Assert.NotNull(createdProduct);
Assert.Equal("Test Product", createdProduct.Name);
Assert.Equal(29.99m, createdProduct.Price);

Why Multiple Assertions?

  • Status Code: Confirms the operation succeeded (201 Created)
  • Not Null: Ensures a product was returned in the response
  • Property Values: Verifies the response contains expected data

Together, these assertions provide comprehensive validation of the endpoint's behavior.

Testing Database Integration

Why Test Database Persistence?

Beyond HTTP Responses: While the previous test verified the HTTP response, it doesn't confirm that data was actually saved to the database. This test directly queries the database to ensure persistence works correctly.

Creating the Database Integration Test

[Fact]
public async Task CreateProduct_SavesToDatabase()
{
    // Arrange
    var newProduct = new
    {
        Name = "Database Test Product",
        Price = 49.99
    };
    
    // Act
    var response = await _client.PostAsJsonAsync("/api/products", newProduct);
    
    // Assert - Verify HTTP response
    response.EnsureSuccessStatusCode();
    
    // Assert - Verify database persistence
    using var scope = _factory.Services.CreateScope();
    var dbContext = scope.ServiceProvider.GetRequiredService<AppDbContext>();
    
    var savedProduct = await dbContext.Products
        .FirstOrDefaultAsync(p => p.Name == "Database Test Product");
    
    Assert.NotNull(savedProduct);
    Assert.Equal(49.99m, savedProduct.Price);
}

Understanding Database Access in Tests

Creating a Service Scope

using var scope = _factory.Services.CreateScope();
var dbContext = scope.ServiceProvider.GetRequiredService<AppDbContext>();

Why Create a Scope?

  • DbContext Lifetime: DbContext is registered as scoped, meaning one instance per request
  • Service Isolation: Creating a scope provides a fresh DbContext instance
  • Proper Disposal: The using statement ensures proper cleanup
  • Avoiding Conflicts: Prevents interference with the DbContext used by the HTTP request

Querying the Database

var savedProduct = await dbContext.Products
    .FirstOrDefaultAsync(p => p.Name == "Database Test Product");

Direct Database Query: This LINQ query:

  • Queries the in-memory database directly
  • Searches for a product with the specific name
  • Returns the first matching product or null
  • Verifies the product was actually persisted

Verifying Persistence

Assert.NotNull(savedProduct);
Assert.Equal(49.99m, savedProduct.Price);

Assertions Confirm:

  • The product was saved to the database (not null)
  • The price was stored correctly
  • The complete workflow from HTTP request to database works

Complete Workflow Validation

End-to-End Verification: This test confirms that the complete workflow functions correctly:

  1. HTTP POST request is received
  2. JSON data is deserialized to Product object
  3. Controller processes the request
  4. Product is added to DbContext
  5. SaveChangesAsync() persists to database
  6. HTTP response is returned
  7. Data remains in database after request completes

Complete Integration Test Class

Full Test Class Implementation

public class ProductsControllerIntegrationTests 
    : IClassFixture<CustomWebApplicationFactory<Program>>

    private readonly CustomWebApplicationFactory<Program> _factory;
    
    public ProductsControllerIntegrationTests(
        CustomWebApplicationFactory<Program> factory)
    {
        _factory = factory;

    }

        Assert.Equal(HttpStatusCode.Created, response.StatusCode);
        
        var createdProduct = await response.Content.ReadFromJsonAsync<Product>();
        Assert.NotNull(createdProduct);
        Assert.Equal("Test Product", createdProduct.Name);
        Assert.Equal(29.99m, createdProduct.Price);

    [Fact]

Testing PUT and DELETE Operations

[Fact]
public async Task UpdateProduct_ValidData_ReturnsNoContent()
{
    // Arrange - Create a product first
    var createResponse = await _client.PostAsJsonAsync("/api/products", new
    {
        Name = "Original Name",
        Price = 10.00
    });
    
    var createdProduct = await createResponse.Content.ReadFromJsonAsync<Product>();
    
    // Act - Update the product
    var updatedProduct = new
    {
        Id = createdProduct.Id,
        Name = "Updated Name",
        Price = 15.00
    };
    
    var response = await _client.PutAsJsonAsync(
        $"/api/products/{createdProduct.Id}", 
        updatedProduct);
    
    // Assert
    Assert.Equal(HttpStatusCode.NoContent, response.StatusCode);
}

[Fact]
public async Task DeleteProduct_ExistingId_ReturnsNoContent()
{
    // Arrange - Create a product first
    var createResponse = await _client.PostAsJsonAsync("/api/products", new
    {
        Name = "To Be Deleted",
        Price = 5.00
    });
    
    var createdProduct = await createResponse.Content.ReadFromJsonAsync<Product>();
    
    // Act
    var response = await _client.DeleteAsync($"/api/products/{createdProduct.Id}");
    
    // Assert
    Assert.Equal(HttpStatusCode.NoContent, response.StatusCode);
    
    // Verify deletion
    var getResponse = await _client.GetAsync($"/api/products/{createdProduct.Id}");
    Assert.Equal(HttpStatusCode.NotFound, getResponse.StatusCode);
}

Testing with Multiple Items

[Fact]
public async Task GetProducts_ReturnsMultipleProducts()
{
    // Arrange - Create several products
    var products = new[]
    {
        new { Name = "Product 1", Price = 10.00 },
        new { Name = "Product 2", Price = 20.00 },
        new { Name = "Product 3", Price = 30.00 }
    };
    
    foreach (var product in products)
    {
        await _client.PostAsJsonAsync("/api/products", product);
    }
    
    // Act
    var response = await _client.GetAsync("/api/products");
    
    // Assert
    response.EnsureSuccessStatusCode();
    var retrievedProducts = await response.Content
        .ReadFromJsonAsync<List<Product>>();
    
    Assert.NotNull(retrievedProducts);
    Assert.True(retrievedProducts.Count >= 3);
}

Integration Testing Best Practices

Test Design Principles

  • Test Complete Workflows: Integration tests should validate entire request/response cycles
  • Use Realistic Data: Test with data that resembles production scenarios
  • Verify Multiple Aspects: Check status codes, response data, and database state
  • Test Both Success and Failure: Include tests for error conditions
  • Keep Tests Independent: Each test should work regardless of execution order

Database Testing Strategy

  • Use In-Memory Database: Fast execution without external dependencies
  • Fresh State Per Test: Each test starts with a clean database
  • Verify Persistence: Query the database directly when testing data operations
  • Test Relationships: Verify foreign keys and navigation properties work correctly

HTTP Testing Techniques

  • Use Appropriate Methods: GetAsync, PostAsJsonAsync, PutAsJsonAsync, DeleteAsync
  • Verify Status Codes: Check for 200 OK, 201 Created, 204 No Content, 404 Not Found, etc.
  • Read Response Content: Deserialize JSON to verify response data
  • Test Headers: Verify Location headers for created resources

Test Organization

  • One Test Class Per Controller: Keep related tests together
  • Descriptive Test Names: Names should explain what's being tested
  • Arrange-Act-Assert: Follow AAA pattern for clarity
  • Share Test Infrastructure: Use IClassFixture to share WebApplicationFactory

Key Concepts Summary

Integration Test
A test that validates multiple components working together, from HTTP request through the application stack to the database and back, ensuring complete workflows function correctly.
PostAsJsonAsync
An HttpClient extension method that automatically serializes an object to JSON, sets the correct content type, and sends it as the request body in a POST request.
EnsureSuccessStatusCode
A method that verifies an HTTP response has a 2xx success status code and throws an exception if the status indicates an error, causing the test to fail.
ReadFromJsonAsync
An extension method that reads the HTTP response content and deserializes it from JSON to a specified .NET type.
Service Scope
A container for scoped services that are created and disposed together. Required when accessing scoped services like DbContext outside of a web request.
Database Persistence Testing
Verifying that data operations result in actual database changes by querying the database directly, not just checking HTTP responses.
HttpStatusCode
An enumeration of standard HTTP status codes (200 OK, 201 Created, 404 Not Found, etc.) used to verify endpoint responses in tests.
Complete Workflow Validation
Testing the entire path from HTTP request through routing, controllers, business logic, database operations, and back to the HTTP response.
